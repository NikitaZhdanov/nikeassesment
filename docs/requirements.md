# Product catalog requirements

Status: implementation baseline. Changes to behavior start here, then flow through use cases, design, tasks, and tests.

## Scope and assumptions

A REST backend owns a catalog of approximately 300,000 products. Reads greatly outnumber writes. Clients maintain products and browse by category and price. The first version is a single EUR catalog: `price_cents` is an integer number of euro cents, never a floating-point amount. This currency choice is an explicit assumption and can be changed before deployment.

Authentication, authorization, inventory, orders, images, product variants, category management, full-text search, multi-currency pricing, bulk imports, and public deployment are outside this version. Run behind a trusted gateway if exposed beyond local development. No user identity is inferred from requests.

## Functional requirements

| ID | Requirement and acceptance criteria |
| --- | --- |
| FR-01 | Create a product with `POST /v1/products`. Return 201, a Location header, and the persisted representation. Generate a UUID and UTC creation/update timestamps on the server. |
| FR-02 | Retrieve a product by UUID with `GET /v1/products/{id}`. Return 200 or 404. A malformed UUID returns 400. |
| FR-03 | Replace all editable fields with `PUT /v1/products/{id}`. Return 200; preserve ID and creation time; advance update time. Missing products return 404, never an implicit insert. Concurrent writes use last committed write wins: each successful replacement is atomic, and the persisted row is one complete committed replacement, never a mixture of fields. |
| FR-04 | Hard-delete a product with `DELETE /v1/products/{id}`. Return 204 with no body; subsequent reads/deletes return 404. |
| FR-05 | List products with `GET /v1/products`, optionally filtering by exact category and inclusive `min_price_cents` / `max_price_cents`. Filters combine with AND. Missing bounds are unbounded. Empty results return 200 and `items: []`. |
| FR-06 | Order lists by `(price_cents ASC, id ASC)`. Use opaque forward cursors; default limit 20, allowed range 1–100. Return `next_cursor` only when another row exists (otherwise null). No offsets, total counts, or page numbers. With unchanged data, pagination returns every matching product exactly once, including equal-price products. |
| FR-07 | Validate writes and filters. Require exact, case-sensitive JSON property names. Reject unknown/case-variant properties, duplicate properties (including identical or Unicode-escaped equivalents), multiple JSON values, malformed UTF-8, NUL in writable strings (including JSON `\u0000`), missing/null required values, malformed JSON, unsupported query parameters, repeated query keys, invalid ranges, invalid cursors, and cursors reused with changed filters. Return 400 with a stable JSON error envelope. |
| FR-08 | SKUs are case-sensitive, unique uppercase identifiers matching `[A-Z0-9][A-Z0-9_-]{0,63}`. Duplicate SKU on create/update returns 409, with database enforcement under concurrency. |
| FR-09 | `GET /healthz` reports process liveness; `GET /readyz` probes database availability. Readiness returns 503 when PostgreSQL is unavailable. |

## Product contract

| Field | Writable | Constraints |
| --- | --- | --- |
| id | No | UUID, generated by service |
| sku | Yes, required | 1–64 ASCII characters; pattern above |
| name | Yes, required | 1–200 Unicode characters; whitespace-only values rejected; surrounding whitespace preserved |
| description | Yes, optional | Up to 5,000 Unicode characters; omitted or null means empty string on replacement |
| category | Yes, required | 1–64 characters; lowercase slug `[a-z0-9]+(-[a-z0-9]+)*` |
| price_cents | Yes, required | Integer 0–1,000,000,000,000 inclusive; null/missing invalid; zero allowed |
| created_at, updated_at | No | UTC RFC 3339 timestamps |

Write bodies must be valid UTF-8 before JSON decoding. Valid multibyte characters and JSON Unicode escapes are accepted, and name whitespace is preserved. NUL is forbidden in all writable strings because PostgreSQL text cannot store it. The 64 KiB limit includes trailing whitespace; oversized JSON writes return 413.

## Non-functional requirements

| ID | Requirement and verification |
| --- | --- |
| NFR-01 | PostgreSQL durably stores all products. Successful writes are immediately visible to subsequent reads from the primary. Database constraints backstop API validation. |
| NFR-02 | Bounded list responses and keyset queries support hundreds of thousands of rows without deep OFFSET scans. Provide a reproducible 300,000-row query-plan experiment; latency depends on deployment hardware and is not claimed without measurement. |
| NFR-03 | Use established Go libraries for routing, validation, database access, assertions, and database mocks. Pin dependencies in go.mod/go.sum. |
| NFR-04 | Unit tests alone must cover at least 90% of first-party Go statements across all production packages, including command wiring. The automated coverage gate must fail below 90%; integration/E2E results cannot inflate it. Run race detection and go vet. |
| NFR-05 | Persistence integration tests must execute migrations and real PostgreSQL CRUD, filters, constraints, concurrent uniqueness, concurrent full replacements with controlled commit order, and pagination. A requested integration run must fail when no test database is configured. |
| NFR-06 | Black-box HTTP E2E tests must cover every numbered use case using Docker Compose with isolated PostgreSQL, migrations, the real API image, and a test runner. Test failures propagate to the command exit status; teardown removes only the test project's resources. |
| NFR-07 | Accept JSON writes only (415 otherwise); cap bodies at 64 KiB (413). Bound HTTP/database operations, handle graceful shutdown, use parameterized SQL, and return generic server errors without leaking SQL/credentials. Product operations return 404 for missing products, 409 for duplicate SKU, 400 for invalid client input, 503 for database connection/availability failures or database-operation timeouts, and 500 for unexpected SQL/driver/internal persistence failures. Emit structured request logs and request IDs. |
| NFR-08 | README documents purpose, required Go/Docker/PostgreSQL versions, configuration, startup, migrations, API examples, test commands, coverage, and known limitations. CI runs the same checks. |
| NFR-09 | GitHub Actions exposes separate unit-coverage, static-analysis, security, and system-test checks on pushes and pull requests. Static checks enforce gofmt, go vet, and pinned Staticcheck across production and tagged test code. Security checks verify downloaded module integrity and run pinned govulncheck against production/test dependencies and the Go standard library. Reachable vulnerability findings and scanner errors fail the job. Run checks weekly and on manual dispatch as well; Dependabot proposes weekly Go-module, Actions, Docker-image, and Compose-image updates. Development tools must add no application runtime dependencies. |

Pagination is a live view, not a snapshot: inserts, deletes, and changes to price/category between requests can change membership or cause a product to be skipped/repeated. Snapshot exports would require a separate contract. A cursor binds filters but does not bind page size; clients may change `limit` between pages.
